# PID制御

## 川の枠（2026-11-18〜）

古いページを面白くする施策の 1 本目である。今のページは機能が足りている一方で、動かして体験し、興味を持てる要素が弱かった（ユーザーの指摘）。流れのある川をボートが進む絵を足し、PID が流れや手出しに逆らって位置を保ち続ける様子を見せる。

### 決めたこと

- 案 B（触れる川）と案 C（3 つの力）を組み合わせる（ユーザーの判断）
- 組み合わせ方は「ライブの川を主役にし、100 s の計算はその下に残す」（ユーザーの判断）
- 今の機能を使えなくする改良は受け入れない（ユーザーの条件）
- P・I・D の矢印の表示は切り替えのオプションにする（ユーザーの提案）
- 水の抵抗を既定で入れ、既定のゲインもそれに合わせて変える（案 1、2026-11-18 ユーザーの判断）
  - 抵抗がないと PID を切っても流されず、止まると推力が 0 になって矢印が消えるため
- 100 s の表示窓と計算をやめ、川の枠に一本化する（2026-11-18 試作 1 回目のあとのユーザーの指摘）
  - 試作 1 回目ではブイを動かしても入力の目標位置が変わらず、ボートとグラフが入力と連動していないように見えた
  - 川の枠の 2 枚の表示窓で 100 s の表示窓を代用できる（ユーザーの判断）
- 計算結果は畳み、ブロック図は小さくしてよい。配置も変えてよい（ユーザーの判断）
- 計算（事前の計算）とライブの 2 つのモードを置く（2026-11-18 試作 2 回目のあとのユーザーの指摘）
  - ライブだけでは、ボートが左右に動く中でゲインを調整するのが直感的でない
  - 計算のモードではゲインを動かしてすぐグラフを見ながら調整できる
- P・I・D の係数を自動で調整するボタンを置く（ユーザーの提案）
- 内訳の表示窓の線（P・I・D・u・推力）が似ているので、出す線を選べるようにする（ユーザーの指摘）

### 計算のモード（既定）

- 川の枠の右上の「計算・ライブ」で切り替える。選んだモードは保存する
- 100 s のステップ応答を前もって計算し、川で再生する（案 A の再生）。終わりで少し止まってから頭へ戻る
- 表示窓は 0〜100 s（10 s/div、札は STEP）。再生の位置に縦線。表示窓を押す・なぞるとその時刻へ
- 入力を変えるとすぐ計算し直す。ゲインなどは同じ時刻のまま新しい結果へ、x<sub>0</sub>・r・v<sub>0</sub> は頭から
- ブイを離すと入力の r を変えて計算し直す
- 押すボタンと PID の入切は出さない（場所は残す）。「最初から」は再生を頭へ戻す
- 計算結果は旧ページと同じ 100 s のステップ応答の指標（終了時の偏差）

### 自動調整

- PID ゲインの枠の右上の「自動調整」
- 今の制御対象と x<sub>0</sub>・r・v<sub>0</sub> で 100 s のステップ応答を計算し、ITAE が最小のゲインを選ぶ
- 条件: 100 s 以内に整定・行き過ぎ 5 % 以下・流れに対する速さ 10 m/s 以下（速さの上限がないと、模型に推力の上限がないので非現実的に速いゲインを選ぶ）
- 候補はゲインの入力と同じ 0 と E12。10 進の 1 桁に 4 つの組み合わせをすべて試し（約 1 万通り）、隣の値へ動かして詰める。PC で 0.15 s ほど
- 既定の制御対象では既定のゲインがそのまま選ばれる
- 条件を守れる組がないとき（下流の目標など）は、超える分が最も小さい組にし、K<sub>P</sub> の行にその旨を出す
- 初期位置と目標位置が同じなら調整しない

### 内訳の表示窓の札

- P・I・D・u・推力の札を押して、線と川の矢印の両方を出し入れする。初めは P・I・D。選びは保存する
- 縦の範囲は出している線だけで決める
- 「表示の設定」の矢印の選択（推力・P・I・D）はこの札に置き換えた

### 残すもの

- PID ゲイン・制御対象の入力と、値の打ち込み・保存
- 速度の表示（位置の表示窓の CH2 に移した）
- ブロック図・計算結果の 7 指標・上部の要約のバー
- 動作原理と式・代入した最初のステップ

### 画面の構成

- PC は 2 列
  - 左の列: 「川」の枠（図・押すボタン・2 枚の表示窓・表示の設定）
  - 右の列: PID ゲイン・制御対象・ブロック図（最大 340 px）・計算結果（初めは閉じる）
  - その下に動作原理と式（全幅）
- スマートフォンは 川 → PID ゲイン → 制御対象 → ブロック図 → 計算結果 → 動作原理と式
- 2 列のページなので、川の枠も開閉できる
- 枠線の上の右端
  - 開始・停止の LED 付きトグル
  - PID の入・切の LED 付きトグル
- 図の上の表示の行（`.sbar`）: 時刻 t・位置 x・誤差 e。発散と、画面の外へ出たときの知らせ
- 図: 上から見た川・岸の距離の目盛り（m）・ブイ（目標）・出発の杭・ボート・矢印
- 図の下の押すボタンの行: 「← 押す」「押す →」「最初から」。倒立振子の `.pushbar` と同じ形にする
- 直近 60 s の表示窓（ロール表示）を縦に 2 枚
  - 位置: CH1 に位置 x とブイの位置 r（破線）。CH2 に流れに対する速度 v と位置を保つのに要る速度 −w（破線）。CH2 は札のボタンで出し入れし、初めは隠す
  - 操作量の内訳: P・I・D の表示のときだけ出す
  - どちらもオシロスコープ表示の形（CH の札・/div）にそろえる
- 「表示の設定」（`More`）に次を畳む
  - 再生の速さ: 実時間・×2・×5。既定 ×2
  - 矢印: 推力・P・I・D。既定 P・I・D

### 動き

- 開いて図が画面に入ると動き始める。画面の外とタブが隠れている間は止める
- 動きを減らす設定では自動で始めず、時刻 0 の絵を出す。開始を押せば動く
- 計算の刻みは今と同じ Δt = 0.1 s で、再生の速さだけを変える
- 描くときは前のステップと今のステップの間を補い、ボートと矢印と泡を滑らかに動かす（試作 1 回目でカクカクすると指摘）
- 表示窓はステップが進んだときだけ描き直す
- 開始・停止・PID の入切・ライブの状態は保存しない
- 再生の速さ・矢印の選択・CH2 の表示は保存する

### 操作

- ブイをドラッグすると目標が変わる
  - 離したときに入力の目標位置 r へ戻す（入力の値も保存される）
  - 図の範囲と入力の範囲（±100 m）の中に限る
- 押すボタンはボートの速さを ±2 m/s 変える
- 図にフォーカスがあるとき、← → で押す。Shift と ← → でブイを 1 m 動かす
- 「最初から」で入力の x<sub>0</sub>・v<sub>0</sub>・r から始め直す
- PID を切ると操作量 u を 0 にし、推力は 1 次遅れで 0 へ戻る（私の判断）
  - 切の間は積分を止め、P・I・D の矢印と内訳の線は 0 で描く
  - 入に戻すと積分を 0 から始め、前回の誤差を今の誤差にそろえる。戻した瞬間の微分項の跳ねを避ける
- ライブで |x| か |v| が 10<sup>6</sup> を超えたら止め、表示の行に DIVERGED を出す（私の判断）
  - 札と閾値は旧 100 s の表示窓と同じ。「最初から」で戻る
- 入力を変えたとき
  - K<sub>P</sub>・K<sub>I</sub>・K<sub>D</sub>・w・α・水の抵抗はその場でライブに効く
  - r を変えたらブイを動かす。図の外なら図の範囲を広げる
  - x<sub>0</sub>・v<sub>0</sub> を変えたら最初から始め直す

### 計算結果

最後の出来事からの応答を測る（倒立振子の「押してから」と同じ考え方）。

- 出来事: 最初から・目標の変更（ブイを離した・Shift と矢印キー・入力）・押す・PID を入れる
- 整定時間: 帯に入って 10 s 留まったとき、入った時刻を出す。出るまでは —
- 帯: 出来事の時の位置から目標までの距離の ±2 %、少なくとも ±0.5 m
- 立ち上がり時間・オーバーシュート・ピーク時刻: 目標が 1 m 以上動いた出来事だけ
- 終了時の偏差は今の偏差 e にした
- 抵抗なしの旧既定値では、最初からの整定時間が旧 100 s の計算と同じ 14 s になる

### 図の描き方

- 水の筋は流速 w で流れる。泡は船尾から出て、水と一緒に流れる
- 図の範囲は入力の x<sub>0</sub> と r から決め、両側に余白を取る。「最初から」と、目標が図の外へ出たときだけ決め直す
- ボートが範囲の外へ出たら、端に「画面の外」の印を出す
- 矢印の表示は「推力」と「P・I・D」の二択にする（私の判断）
- 推力の矢印は 1 次遅れのあとの実際の推力 a/Δt を表す
- P・I・D の矢印は制御器の出力の内訳（K<sub>P</sub>e・K<sub>I</sub>∫e・K<sub>D</sub>de/dt）と、その合計 u を表す
  - 1 次遅れの前の値なので、合計 u と推力はずれる。ずれが α の効き目である
  - 内訳の表示窓には推力も細い線で重ね、このずれを見せる（私の判断）
- 矢印の長さは飽和する目盛り（tanh）で、ブイを急に動かしたときの微分項の跳ねは最大の長さで出す
- 内訳の表示窓の縦の範囲は跳ねを除いた値で決め、跳ねは上下の端で切る（私の判断）
  - 自動の範囲では、t = 0 の微分項（既定で約 165）に比べて P と I が平らな線になるため

### 水の抵抗

今の模型には抵抗がない。P と D だけで偏差なく目標に着くので、積分項の「残った偏差を消す」働きが見えない。そこで制御対象の入力に「水の抵抗」を足す。

- 記号 c・単位 1/s・既定 0.047
- 範囲 0〜1。刻みは 0 と 0.001 以上の E12
- プリセット: 0・0.01・0.047・0.1
- 速度の式を v<sub>k+1</sub> = v<sub>k</sub> + a<sub>k+1</sub> − c v<sub>k</sub> Δt にする
- c = 0 のとき、旧 100 s の計算の結果と一致させる（model.ts の simulate を基準としてテストで突き合わせる）
- 既定のゲインは K<sub>P</sub> 0.015・K<sub>I</sub> 0.00022・K<sub>D</sub> 0.27（それまでは 0.0047・0・0.33）
  - 整定時間 9.3 s・オーバーシュート 1.8 %（それまでは 14.0 s・6.9 %）
  - c を 0 にし、ゲインをそれまでの値に戻すと、それまでの結果と一致する
- 動作原理と式・ブロック図に抵抗の項を足す

### 色

- P は ch1 の黄、I はページだけの紫（明 #a03c8c・暗 #e58ad6）、D は ch2 のシアン、合計 u はインク色
- ブイは赤（`--ic-red`）
- 水・岸の色はこのページだけの色として決める
